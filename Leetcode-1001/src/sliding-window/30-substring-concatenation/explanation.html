Explanation for 30. Substring with Concatenation of All Words

This document explains the logic behind the `findSubstring` function, which solves LeetCode Problem 30: "Substring with Concatenation of All Words".

Problem Statement

You are given a string `s` and an array of strings `words`. All the words in `words` are of the same length. Your task is to find all starting indices in `s` of substring(s) that is a concatenation of each word in `words` exactly once and without any intervening characters.

For example, if `s = "barfoothefoobarman"` and `words = ["foo","bar"]`, the output should be `[0, 9]` because "barfoo" (starting at 0) and "foobar" (starting at 9) are concatenations of "foo" and "bar".

Algorithm: Sliding Window with Nested Iteration

The core idea here is a brute-force approach optimized by a fixed-size sliding window. Since all words in `words` have the same length, we know the exact size of the target substring we are looking for (words.length * wordSize).

1. Preprocessing (Building `wordsMap`)

First, we count the frequency of each word in the `words` array. This is stored in a `Map` called `wordsMap`. This map acts as our reference for what words we need to find and how many times.


const wordSize = words[0].length;
const windowSize = words.length * wordSize;
const wordsMap: Map = new Map();
// ...
for (const word of words) {
    wordsMap.set(word, (wordsMap.get(word) || 0) + 1);
}

2. Outer Loop: Iterating through potential starting points

We use an outer loop that iterates from `i = 0` up to `s.length - windowSize`. Each `i` represents a potential starting index for a valid concatenation substring in `s`.


for (let i = 0; i <= s.length - windowSize; i++) {
    // ...
}

3. Inner Loop: Checking the current window

Inside the outer loop, for each potential starting index `i`, we establish a "window" of size `windowSize` starting at `i`. We then iterate through this window, taking chunks of `wordSize` length.

  • A temporary `Map` (`map`) is created as a copy of `wordsMap`. This temporary map will be modified to keep track of words found within the current window.
  • `matchCount` is initialized to 0. This variable will count how many unique words from `wordsMap` have been fully matched (i.e., their count in `map` drops to 0).
  • The inner loop `j` starts at `i` and increments by `wordSize` until it reaches `i + windowSize - wordSize`.
  • In each step, `s.substring(j, j + wordSize)` extracts a `wordSize`-length chunk (`currentWord`).
  • We check if this `currentWord` is present in our temporary `map` and if its count is greater than 0.
  • If it is, we decrement its count in `map`. If its count becomes 0 after decrementing, it means we have found all occurrences of this specific word that we needed, so we increment `matchCount`.
  • If at any point `matchCount` equals `map.size` (meaning all unique words from `words` have been found the correct number of times within the current window), then we have found a valid concatenation. The starting index `i` is added to our `ans` array, and we `break` out of the inner loop to move to the next `i` in the outer loop.

    let matchCount = 0;
    const map = new Map(wordsMap); // Create a fresh copy for each window

    for (let j = i; j <= i + windowSize - wordSize; j += wordSize) {
      const currentWord = s.substring(j, j + wordSize);
      const wordCount = map.get(currentWord);

      if (wordCount && wordCount > 0) {
        map.set(currentWord, wordCount - 1);
        if (map.get(currentWord) === 0) {
          matchCount++;
        }
      } else {
        // If the word is not in our original words list, or its count is already 0,
        // this window cannot be a valid concatenation. Break early.
        break;
      }

      if (matchCount === map.size) {
        ans.push(i);
        break; // Found a match for this 'i', move to next outer loop iteration
      }
    }

Note: The `else { break; }` condition added above is an optimization. If a word is encountered that is not in the original `words` list or if we've already matched all required instances of that word for the current window, then this particular window cannot be a valid concatenation, and we can stop checking it early.

TypeScript Code (`findSubstring`)


export function findSubstring(s: string, words: string[]) {
  const wordSize = words[0].length;
  const windowSize = words.length * wordSize;
  const wordsMap: Map = new Map();
  const ans: number[] = [];

  for (const word of words) {
    wordsMap.set(word, (wordsMap.get(word) || 0) + 1);
  }

  // Iterate through all possible starting positions for the full window
  for (let i = 0; i <= s.length - windowSize; i++) {
    let matchCount = 0;
    const map = new Map(wordsMap); // Create a fresh copy of wordsMap for each window check

    // Iterate through the current window in chunks of wordSize
    for (let j = i; j <= i + windowSize - wordSize; j += wordSize) {
      const currentWord = s.substring(j, j + wordSize);
      const wordCount = map.get(currentWord);

      if (wordCount && wordCount > 0) {
        map.set(currentWord, wordCount - 1);
        if (map.get(currentWord) === 0) {
          matchCount++; // This unique word is fully matched in this window
        }
      } else {
        // If the current word is not in our dictionary, or we've already used up its quota
        // for this window, then this window cannot be a valid concatenation.
        break;
      }

      // If all unique words are matched in this window
      if (matchCount === map.size) {
        ans.push(i); // Add the starting index of this valid concatenation
        break; // Move to the next potential starting position in the outer loop
      }
    }
  }

  return ans;
}

Complexity Analysis

  • Time Complexity: O(N * M * L)
    • N is the length of string `s`.
    • M is the number of words in `words`.
    • L is the length of each word.
    • The outer loop runs `N - windowSize + 1` times (approx. `N`).
    • The inner loop runs `words.length` times (approx. `M`).
    • Inside the inner loop, `substring` takes `O(L)` time, and `Map` operations (`get`, `set`) take `O(L)` time in the worst case (if string hashing is `O(L)`).
    • Therefore, total time complexity is roughly `N * M * L`.
  • Space Complexity: O(M * L)
    • `wordsMap` stores `M` words, each of length `L`.
    • The temporary `map` also stores `M` words.
    • The `ans` array stores up to `N` indices.
    • So, space complexity is dominated by the maps, approximately `O(M * L)`.
